# Power BI semantic model

## Open and refresh locally

1. Keep credentials in the ignored project-root `.env` file (`FRED_API_KEY` and `BOT_API_KEY`). Never paste keys into Power BI or commit the file.
2. From the project root, run `python -m fx_intelligence.ingestion.build_local --start 2026-01-01 --end 2026-09-30` to produce the local DuckDB warehouse and `dashboard/powerbi/data/fx_model.xlsx`. Adjust the dates for the desired coverage. This command calls official APIs, so it needs network access and the subscribed BOT Exchange Rates product.
3. Open `dashboard/powerbi/FX Market Intelligence Dashboard.pbip` in Power BI Desktop. The model currently points to this workstation's absolute workbook path. On a different machine, use **Transform data > Data source settings > Change Source** (or edit the nine `File.Contents` paths in the TMDL definitions) to point to the newly generated workbook.
4. Choose **Refresh** in Power BI Desktop after rebuilding the workbook. Rebuilding the workbook alone does not refresh Power BI's imported model. Never publish the report with embedded credentials or generated source data without reviewing sharing rights and access.

The Excel workbook and CSV extracts are generated local artifacts and are ignored by Git. The `.pbip` project, TMDL model and report definition are source controlled. The PBIP can open on a clean checkout after the workbook has been generated and the local source path has been set.

## Tables and grain

| Table | Grain / role | Key or date |
| --- | --- | --- |
| `tbl_dim_date` | one calendar day, including non-observation days | `date_key` |
| `tbl_dim_fx_pair` | one directed quote | `pair_id` |
| `tbl_dim_source` | one provider series source | `source_id` |
| `tbl_dim_indicator` | one macro series | `indicator_id` |
| `tbl_dim_currency` | one currency, descriptive metadata | `currency_code` |
| `tbl_fact_fx_rates` | source × pair × observation date × rate type | positive quote rate |
| `tbl_fact_fx_metrics` | same FX grain, analytical outputs from Python | indexed rate, return, drawdown, volatility |
| `tbl_fact_macro` | source × series × observation date × vintage | provider value and provenance |
| `tbl_refresh_metadata` | one successful local build | timestamp and row counts |

Relationships are active, single-direction many-to-one from each fact to `tbl_dim_date`, `tbl_dim_source`, and relevant pair or indicator dimensions. Date relationships use observation dates. Vintage and release dates remain separate attributes, not substitutes for observation date. `tbl_dim_currency` is a descriptive table; pair slicers use `tbl_dim_fx_pair` so an ambiguous base/quote relationship is not introduced. The Power BI auto-date tables attached to retrieval timestamps are generated by Desktop; time-series visuals should use the explicit `tbl_dim_date` table.

Excel table import exposes date-only cells as numeric serials in Navigator. The model's Power Query steps convert them to `type date`, and the TMDL columns use `dateTime`. This conversion follows Power Query's OLE Automation date handling. Macro `release_date` remains blank when the provider payload did not supply it.

## Measures and filters

- **Latest FX Rate**: last observed rate in the current date filter, only when source, pair and rate type each resolve to one value. This avoids mixing BOT interbank and bank average rates.
- **Latest Observation Date**: last available FX observation under the same single-series requirement.
- **Latest Simple Return**: most recent daily simple rate return for the selected single series. Positive USD/THB return means THB depreciation because USD/THB is THB per USD.
- **Latest 20D Volatility**: most recent annualized 20-observation sample standard deviation of log returns, multiplied by √252. It is a fraction formatted as a percentage.
- **Last Refresh**: successful warehouse build timestamp from `tbl_refresh_metadata`; a Power BI refresh is still required for the displayed value to update.

Use `tbl_dim_fx_pair[pair_id]`, `tbl_dim_source[source_id]`, `tbl_fact_fx_rates[rate_type]`, and `tbl_dim_date[date_key]` for FX slicers. Macro visuals use `tbl_dim_indicator[indicator_id]`; keep frequency and unit visible. A single global date slicer filters all three fact tables by observation date, but macro observations and FX trading days have different calendars. Do not infer information availability or causation from same-date visuals.

## Parity and limits

`tests/integration/test_bi_parity.py` compares exported FX return, indexed-rate and volatility values with Python reference calculations using deterministic fixtures. `tests/integration/test_powerbi_model.py` checks TMDL date types, model relationships and required measure definitions. The local live build yielded 543 FX, 603 macro and 543 FX metric rows for the selected 2026 period; those counts describe this build only, not complete provider coverage.

Manual QA on 17 October 2026: the `.pbip` project reopened in Power BI Desktop, refreshed without an error banner, and **Manage relationships** showed all nine intended star relationships as active many-to-one with single-direction filtering. See `dashboard/screenshots/task10-relationships.png`. This verifies model structure and local opening; it does not establish remote Power BI Service refresh or the future six-page report.

The current local feed includes BOT USD/THB interbank, BOT USD/THB and EUR/THB bank averages, and five FRED macro series. JPY scaling and P1 ECB/BIS/BOT macro series need separately verified source rules before inclusion. FRED observation dates and vintages are preserved, but release dates absent from its observation response are not invented. Historical release-aware research therefore remains limited.
